# Google Maps and location checks — KAYAN demos

## Map coverage

Passenger and Driver use Google Maps in browser previews and Android apps. Android renders the native Google Maps SDK through Capacitor; browser previews use the Google Maps JavaScript API. Map loading requires internet access, a valid key, enabled APIs, and a Google Cloud billing account. There is no fallback map.

The Passenger app blocks entry behind a location permission prompt and requires a fresh foreground fix. After permission and a fresh fix, the pickup field defaults to **Current device location** and a pickup marker appears. Selecting a destination requests Google's recommended driving route between the pickup and destination using the Routes API with `TRAFFIC_UNAWARE`. Google returns the route geometry, estimated distance, and duration; these are not dispatch, navigation, guaranteed fastest-route, or live traffic data. The user can switch back to a typed pickup or tap the pickup location button to request a fresh GPS fix; that request can be cancelled while waiting. Passenger coordinates are used only for that preview ride/map and are not displayed as numbers, saved, or sent to KAYAN. The Driver Android demo requires precise foreground location and a fresh fix before entry. Google receives map requests, pickup, and destination to calculate and render the route.

Pickup and destination text, demo rides, stages, estimates, and fares remain simulated. Device coordinates do not become a booking pickup, route, live driver, or real ETA. There is no turn-by-turn navigation, dispatch, payment, upload, or approval. Subscription prices and rewards remain unfinalized.

## Google Cloud key setup

Use two separate Google Cloud API keys:

1. **Android key:** Enable **Maps SDK for Android** and create a key with an API restriction to Maps SDK for Android. The Passenger package is `com.kayan.passenger.demo`; the Driver package is `com.kayan.driver.demo`. Android application restrictions also require the matching signing certificate SHA-1. These demo workflows use CI debug signing certificates, which may change between clean runners; do not add Android app restrictions until the APK is signed with a stable certificate, or the map may reject the key. Never use an unrestricted production key.
2. **Browser key:** Enable **Maps JavaScript API** and **Routes API**, create a separate key, and restrict it to those APIs and the exact referrers used by the browser preview/deployment (including local development origins when needed). Native Android WebView builds that request routes also need an allowed Capacitor WebView referrer. Do not enable or depend on the legacy Directions API. Browser keys are necessarily visible in the client bundle; referrer and API restrictions, quotas, and billing alerts are essential.
3. In Google Cloud Console, verify billing is active on the project and that the enabled API restrictions match each key. Do not paste keys into chat, screenshots, source code, or public issues.
4. For local browser preview, put the browser key in the ignored `.env.local` file as `VITE_GOOGLE_MAPS_API_KEY=...`. For GitHub Actions, add repository secrets `GOOGLE_MAPS_API_KEY` (Android key) and `GOOGLE_MAPS_BROWSER_API_KEY` (browser key). These are used by both Passenger and Driver build workflows. A standalone source-project repository needs the same two secrets.
5. In Android build workflows, the Android key is injected into the generated manifest by `src/android/prepare-android.mjs`. It is extractable from an APK, so Android API restrictions and stable signing identity are important.

Never commit `.env.local`, API keys, signing keystores, or passwords. If an API key was committed or shared publicly, rotate it in Google Cloud Console.

## Android location behavior

The Passenger access prompt and Driver gate request high-accuracy location with no accepted cached age and a 15-second timeout. These settings are requests, not accuracy guarantees or guaranteed timing. Android may use GPS, Wi-Fi, mobile networks, or emulator mock location; the app cannot certify satellite-only or non-mocked readings.

Backgrounding pauses the Driver's foreground location watch; returning to the foreground resumes it. Tracking is not persisted between launches. There is no background-location permission or foreground tracking service. No camera, microphone, contacts, telephone, file, or notification permission is requested because those interactions remain demos.

Native Android manifests and eagle icons are generated by `src/android/prepare-android.mjs` in both APK workflows after Capacitor sync. The script adds coarse/fine foreground permissions, optional GPS hardware, five launcher densities, adaptive icons, and the Google Maps Android key. Each app keeps its separate package ID. Capacitor's internet permission supports map loading.

## Install and test updated builds

Run **Build KAYAN Android demo** and **Build KAYAN Driver Android demo** in GitHub Actions. Download each successful artifact, extract it, and install on a trusted Android test device. New native permissions, plugin, key, and icons require new APKs. Clean CI debug signing can differ between runs; if Android reports an incompatible signature, uninstall the old test app before installing the trusted APK. This clears that app's local preferences. Do not bypass Play Protect.

## Required acceptance checks

1. **App identity:** Install both APKs together. Confirm distinct names/package IDs and KAYAN eagle launcher icons.
2. **Driver launch gate:** Fresh-install Driver; confirm it requests foreground location and remains gated until precise permission and a fresh fix are available. The UI must not display coordinates or accuracy values.
3. **Passenger entry gate:** Fresh-install/open Passenger; confirm the blocking prompt appears and the app cannot be used until foreground location permission is granted and a fresh fix is received. Deny permission and confirm the prompt explains how to retry in browser/device settings.
4. **Passenger GPS pickup:** Confirm the initial fresh fix sets the pickup field and map marker. Tap the pickup location button to request a fresh fix, verify a destination frames both locations, then switch back to typed pickup and confirm the GPS marker/coordinate is no longer used. Verify a pending refresh can be cancelled.
5. **Approximate/denied:** Test approximate-only permission and denial. Driver must remain gated with a clear explanation; switch to Precise in Android app settings and retry. Passenger must remain blocked and show a clear retry/settings prompt.
6. **Services off:** Disable Android Location or internet. Confirm both apps give actionable errors and do not claim a location fix/map is available.
7. **Google Maps key:** Verify Maps SDK for Android, Maps JavaScript API, and Routes API are enabled and restricted appropriately, billing is enabled, and the browser key uses correct referrers. Confirm maps and driving routes load. Do not claim APK app restriction is stable until the signing certificate is stable.
8. **Browser key failure:** Test a browser preview with a missing, invalid, or referrer-blocked browser key. It must show an explicit map configuration/load error, not another map or fictional roads. If route service is rejected or returns no route, no straight-line route should be drawn.
9. **MuMu:** Configure MuMu's simulated location using emulator controls and ensure Google Play Services is present. Confirm the map's device location indicator follows the configured point. Emulator success validates the integration, not physical GPS accuracy.
10. **Physical device:** Test outdoors and indoors on a real Android phone. Compare the map location indicator against a trusted device map/location source and note observed behavior. No numeric accuracy promise is valid without recorded results across devices/environments.
11. **Lifecycle:** Background/lock the Driver app, then return. Confirm location pauses and resumes without duplicate watches. There is no background tracking.
12. **Regression:** Accept/decline, complete/cancel, chat/call demos, earnings/history, pre-registration, and Light/Dark/System must remain simulations. Driver Online does not enable dispatch or share location.
