# Real location and map checks — both KAYAN demos

## What changed

Both apps now use a real Leaflet/OpenStreetMap map and the Capacitor 7 Geolocation plugin on Android (browser geolocation in web previews). Tracking starts only after **Enable device location**. Android requests foreground coarse and fine location together; users may choose approximate access or decline. High accuracy is requested with no accepted cached age, a 15-second update/timeout setting, and a 5-second minimum Android update interval. These settings are requests, not accuracy guarantees or guaranteed timing.

A device marker and accuracy circle show only reported coordinates. The panel shows permission type, device-reported horizontal accuracy in metres, coordinates and fix age. Older than 30 seconds, paused, waiting, or failed fixes are not labelled current; their marker is grey. An accuracy above 50 metres is labelled low accuracy. These are presentation thresholds, not certification that GPS is accurate. Android uses its available location sources, potentially GPS, Wi-Fi, mobile networks or emulator mock location. The app cannot certify satellite-only or non-mocked readings.

**Stop location**, leaving the map screen, app backgrounding and component cleanup clear the location watch. Returning to the foreground resumes an enabled watch, checking permission again. Tracking is not persisted between launches. There is no background-location permission or foreground tracking service. No camera, microphone, contacts, telephone, file or notification permission is requested because those interactions remain demos.

Native Android manifests and eagle icons are generated by `src/android/prepare-android.mjs` in both APK workflows after Capacitor sync. The script adds coarse/fine foreground permissions, optional GPS hardware, five launcher densities and adaptive icons. Each app keeps its separate package ID. Capacitor's default internet permission supports map loading. Existing eagle artwork is kept intact on a forest-green background.

## Map service and privacy

Map images come from `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, with visible attribution, normal browser caching, no offline download/prefetch, and a distinct KAYAN user-agent suffix in native builds. Maps require internet; location availability is independent of tile loading. OpenStreetMap sees the IP and map area requested; no reverse-geocoding or coordinate API is called and no location is saved or sent to KAYAN. Public OSM tiles are best-effort and suitable for limited demo testing, not a guaranteed commercial dispatch map service. Select a contracted map provider and publish contact/privacy information before production or heavy usage.

Pickup and destination text, demo rides, stages, estimates and fares remain simulated. Actual device coordinates do not become a booking pickup, route, live driver or real ETA. There is no turn-by-turn navigation, dispatch, payment, upload or approval. Subscription prices and rewards remain unfinalized.

## Install updated test builds

In GitHub Actions run **Build KAYAN Android demo** and **Build KAYAN Driver Android demo**, download each successful artifact, extract and install on your trusted Android test device. The new native permissions/plugins/icons require new APKs; refreshing the old APK cannot add them. Clean CI debug signing can differ between runs; if Android reports incompatible signatures, uninstall the old test app before installing the new trusted APK. This clears that app's local preferences. Do not bypass Play Protect.

## Required acceptance checks

1. **Logo:** Install both APKs together. Confirm both show the KAYAN eagle (including round/adaptive launcher masks), different app names, and separate package IDs. Confirm eagle branding appears on mobile headers and browser favicon.
2. **Permission timing:** Fresh install should not prompt for location until Enable device location. Choose While using the app and Precise. Confirm a marker, coordinates, permission type, fix age and reported accuracy appear. No other runtime permissions should be requested.
3. **Approximate/denied:** Test Approximate-only and denial. Approximate is visibly indicated; denial must not invent a position or stop demo bookings. For permanent denial, grant permission through Android App settings and retry.
4. **Services off:** Disable Android Location; retry. Confirm an actionable error and no current-position claim. Turn Location and Google Location Accuracy on; retry.
5. **MuMu:** Configure MuMu's simulated location using the emulator's location controls, choose a known coordinate, enable Android Location and ensure Google Play Services is present. Compare app coordinates with that configured point; change the simulated point and confirm updates. Emulator success validates the integration, NOT physical GPS accuracy.
6. **Physical device:** Test outdoors with clear sky on a real Android phone. Compare with Google Maps/device location at a known point and record horizontal accuracy and fix age. Walk a short route and confirm the marker changes; test indoors too. No numeric accuracy promise is valid without recorded results across devices/environments.
7. **Freshness:** Prevent further location fixes and wait over 30 seconds. Any retained fix must be labelled stale/not current and grey. Never interpret a stale or low-accuracy fix as reliable navigation.
8. **Lifecycle:** Start tracking, background/lock the app, then return. Confirm it pauses and resumes. Stop location and navigate away from the map; Android's location-use indicator should stop (allow OS reporting delay). Check for duplicate watches or updates after stopping.
9. **Map failure:** Test without internet. Tile failures must be visible without replacing missing map data with invented roads. Device fixes may still work if the device has a GPS fix. Reconnect and retry tiles.
10. **Regression:** Accept/decline, complete/cancel, chat/call demos, earnings/history, pre-registration and Light/Dark/System must remain simulations. Driver Online does not automatically request GPS or enable dispatch.
