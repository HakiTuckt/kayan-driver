# Real location and map checks — both KAYAN demos

## What changed

Both apps use the Capacitor 7 Geolocation plugin on Android (browser geolocation in web previews). The passenger map uses Leaflet/OpenStreetMap; the driver map uses Google Maps. A verified live driver uses device location; the driver demo instead uses a fixed, clearly labelled Lusaka demo position so browser/emulator geography cannot move the demo abroad. Passenger location remains opt-in. Android requests foreground coarse and fine location together; the operating system may grant approximate access or deny the request. High accuracy is requested with no accepted cached age; Android uses a 15-second location request interval and 5-second minimum update interval, while browser geolocation allows up to 60 seconds for the initial fix. These settings are requests, not accuracy guarantees or guaranteed timing.

A device marker shows reported coordinates. Older than 30 seconds, paused, waiting, or failed fixes are not labelled current; their marker is grey. Android uses its available location sources, potentially GPS, Wi-Fi, mobile networks or emulator mock location. The app cannot certify satellite-only or non-mocked readings.

Leaving the map screen, app backgrounding and component cleanup clear the location watch. Returning to the foreground resumes enabled tracking, checking permission again. Tracking is not persisted between launches. There is no background-location permission or foreground tracking service. No camera, microphone, contacts, telephone, file or notification permission is requested because those interactions remain demos.

Native Android manifests and eagle icons are generated by `src/android/prepare-android.mjs` in both APK workflows after Capacitor sync. The script adds coarse/fine foreground permissions, optional GPS hardware, five launcher densities and adaptive icons. Each app keeps its separate package ID. Capacitor's default internet permission supports map loading. Existing eagle artwork is kept intact on a forest-green background.

## Map service and privacy

The passenger map uses `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, with visible attribution. The driver uses the native Google Maps Android SDK in APKs and Google Maps JavaScript API in browser previews; Google Routes API calculates driving routes in both. Native map display requires the Android-app-restricted `VITE_GOOGLE_MAPS_ANDROID_API_KEY` (Maps SDK for Android only). Browser maps and route calculation require the website-restricted `VITE_GOOGLE_MAPS_API_KEY` (Maps JavaScript API and Routes API). Both keys need billing, internet access and appropriate package/signing-certificate or website-origin restrictions. During a trip, the fastest returned traffic-aware route leads to the pickup, then to the destination after the driver starts the trip. Verified live-driver navigation uses fresh foreground GPS fixes for visual maneuver updates; the demo uses a labelled Lusaka origin and does not claim real GPS progress. If a live current location is unavailable, no route is fabricated. Map providers receive the IP address and viewed area, and Google receives route origin/destination. Device location is not saved or sent to KAYAN or the passenger. Google Maps billing and usage terms apply to the driver app.

Demo ride details, stages and fares remain simulated. The driver map provides visual foreground guidance only: no spoken directions, background navigation, automatic off-route rerouting, payment, upload or approval. Subscription prices and rewards remain unfinalized.
